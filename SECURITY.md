# Безопасность

DebateMeet пока развивается и проверяется локально. Поддерживаемая ветка — `main`; опубликованных стабильных релизов и обещанного срока исправления пока нет.

## Сообщение об уязвимости

Частный канал для сообщений об уязвимостях пока не подтверждён. Не отправляйте секреты, ссылки на действующие раунды, персональные данные или работающий эксплойт в публичный issue. Чтобы согласовать частный канал с автором, откройте [issue](https://github.com/RuslanPogosyants/DebateMeet/issues/new) только с запросом контакта, без подробностей уязвимости. Включённый GitHub private reporting здесь не предполагается.

Подтверждённый частный канал требуется до запуска стенда. Контакт из закрытого профиля не публикуется без решения автора.

## Модель доступа MVP

- Неугадываемая ссылка даёт доступ к раунду. Аккаунтов и серверных ролей пока нет; любой участник может взять свободный флаг судьи.
- Команды требуют отдельного секрета участника. Он хранится в браузере, поэтому XSS представляет риск угона сессии. Не передавайте его вместе со ссылкой.
- Логические комнаты разделяются клиентскими подписками. Это удобство проведения игры; серверное принуждение приватности комнат отложено.
- Камера и микрофон управляются владельцем. Судья может вручную выключить микрофон или отправить просьбу включить; удалённое включение не разрешено.
- Служебные команды доступны через CLI сервера. Их нет в публичном HTTP API.
- Диагностика принимает только разрешённые технические поля. Имена, чат, резолюция, исходные URL, секреты, SDP и IP в её контракт не входят. Сырые отчёты хранятся 30 дней; обезличенное окно метрик — 28 дней. Это данные, сообщённые клиентом.

HTTPS, CSP, доверенный прокси, закрытые служебные порты, отдельные серверные ключи и резервное копирование описаны в [архитектуре](docs/architecture.md). Локальные проверки и наличие конфигурации не подтверждают развёртывание этих защит на сервере.
