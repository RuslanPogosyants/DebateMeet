# Личное управление медиа и демонстрация экрана

## Решения автора и текущая основа
30.10.2026 автор поручил личную громкость/mute/скрытие чужой камеры прямо на плитке, прямое закрепление и отдельную кнопку демонстрации экрана одновременно с вебкой. Явно выбрано усиление до200%, отменяющее прежний предел100%; физическая акустическая приемка не подменяется кодом. Реализация и локальная проверка разрешены, текущий пользовательский раунд не изменять; использовать отдельный тестовый раунд. Публикация/Git не поручены.

Уже есть SocialSession.volume/setVolume, BrowserPreferences по round+participant, RoundController.setVolume и LiveKitMediaSession.volume. В Room уже webAudioMix с AudioContext; SDK RemoteAudioTrack.setVolume использует gainNode, что допускает2.0. SceneSession владеет pin/showSelf/стабильными12 camera slots и гистерезисом. ParticipantActions содержит резервные текстовые pin/range и отдельные судейские команды. Все это расширяется, не заменяется параллельными владельцами. Текущий token разрешает только microphone/camera; оба LiveKit config ограничивают video subscriptions12.

## Наблюдаемое поведение
- На чужой видеоплитке доступны прямые иконки: pin, личный звук, скрыть/показать камеру. На своей - pin. Троеточие с прежними судейскими/текстовыми действиями сохраняется. Подписи явно «для вас», личные действия не вызывают API mute/request-unmute и не меняют отправителя.
- Звук: click иконки выключает только этого человека у слушателя, повторный click восстанавливает последнее ненулевое значение (fallback100%). Slider0..200%,100%=исходный уровень; движение с0 на ненулевое снимает mute. Значение сохраняется существующим Preferences и переиспользуется после reconnect; последнее ненулевое значение живет в SocialSession, переживает страницы/плитки. NaN/Infinity игнорируются, значения ограничены0..2. Нежелательные/чужие комнаты всегда gain0 независимо от boost.
- Hover500ms по иконке личного звука открывает вертикальный ползунок над ней. Переход на popup его не закрывает. Popup порталом за пределы clipping плитки, позиция ограничена viewport; закрытие Escape/outside/уходом фокуса, cleanup hover timer при unmount/hidden page. Keyboard focus открывает; ArrowUp переводит на range, Escape возвращает на trigger без немедленного повторного открытия. Touch click сохраняет mute, полноценный slider всегда доступен из прежнего текстового меню участника. Новая UI-абстракция владеет только hover/focus/геометрией, громкость принадлежит SocialSession.
- Личное скрытие камеры хранится в SceneSession.hiddenCameraIds на время клиентской сессии, не меняет MediaPerson.camera. Camera video DOM остается стабильным, attachment именно camera снимается; показывается «Видео скрыто для вас». Возврат снова прикрепляет ту же камеру; аудио/экран не затрагиваются. Своя камера управляется прежней нижней кнопкой/showSelf.
- Pin действует в своей комнате; прямое закрепление переключает speaker layout и показывает выбранного человека крупно, снимается повторным нажатием. Прежние сбросы при уходе участника/смене комнаты сохраняются; бюджет/pin13 сохраняются. Это личный выбор, сервер не меняется.
- В dock отдельная44px иконка «Демонстрировать экран» рядом с media. При отсутствии getDisplayMedia кнопка недоступна с понятной подсказкой. Окно выбора источника открывается только непосредственно по click. Захватываем видео экрана без system/tab audio; микрофон и вебка продолжают независимо. Отмена выбора ожидаема и не ломает звонок. Pending-кнопка позволяет отменить ожидающий показ; поздний результат немедленно остановить, ничего не публиковать. При active кнопка «Остановить демонстрацию», на своем screen tile тоже доступна остановка. Browser Stop sharing очищает UI. На leave/ownership loss/dispose все screen tracks останавливаются. Полная новая media session не восстанавливает экран автоматически; короткий SDK reconnect сохраняет только тот же уже разрешенный track.
- Участники видят экраны только своей логической комнаты. Вебка и экран одного человека - разные плитки/HTMLVideoElement, экран не зеркалится и вписывается целиком. SceneSession выбирает screenId из screenIds своей комнаты (включая свой даже при showSelf=false), сохраняет выбор пока доступен, иначе первый доступный. Если экранов несколько, компактный selector выбирает один показываемый. По умолчанию экран крупно в speaker layout; явный pin человека имеет приоритет, экран остается доступной вторичной плиткой. На экране есть действие «Показать экран крупно», снимающее pin человека. В grid экран обычная отдельная плитка; обычная сетка/пагинация сохраняется.

## Интерфейсы и распределение ответственности
- ports.ts: export VideoSource='camera'|'screen'; MediaPerson.screen?:boolean (старые fixtures допустимы); MediaSession.screen(enabled:boolean):Promise<void>; attachVideo(identity,element,source?:VideoSource) defaultcamera. Идентификаторы камер subscribedVideoIds остаются camera-only.
- MediaSession: source-aware video registrations/cleanup keyed identity+source, subscribe только ожидаемый source, снимок своей комнаты обязателен. max12 remote video достигается выбором11camera+1screen, а старые unwanted subscriptions снимаются до новых. screen capture вызывает SDK createScreenTracks({audio:false}) до первого await, затем проверяет revision/closed/session. stop немедленно инвалидирует revision и выключает/stop известный track до await unpublish; поздние capture/publish удаляются, cleanup старой попытки не трогает новый показ. Browser ended SDK unpublish обновляет people.screen. Source-specific callback attach/detach не очищает элемент другого источника. Volume clamp2 на единственном audio owner; SDK gain path проверить реальным SDK-тестом, не только мок-значением.
- Backend: добавить только screen_share в список VideoGrants.can_publish_sources, без screen_share_audio/data. Обновить exact token test. Схема RoundSnapshot/серверные команды не меняются.
- SceneSession: добавить hiddenCameraIds, screenIds, screenId, setCameraHidden(id,hidden), selectScreen(id). Пока screenId неnull камера slots≤11, иначе≤12; pin замещает слот как прежде. Экранные кандидаты не зависят от showSelf. Все screen/localhide состояния очищаются close, список hidden ограничен участниками текущего snapshot. SocialSession: toggleMuted(id), clamp2 и память последнего ненулевого; Preferences clamp2.
- RoundController: generic ToggleKind расширяется screen с отдельным screenIntent, без camera restore flag для экрана. Вызов session.screen начинается синхронно из click path. toggles/revision/generation закрывают поздние события как для camera/mic. toggleParticipantAudio(id) меняет SocialSession и применяет volume. source-aware videos map хранит identity/source/element и rebind после полного reconnect; старый cleanup не удаляет новую регистрацию.
- UI: новый TileControls/volume popup только presentation; camera Tile сохраняет существующий DOM/effect с dependency на localHidden, source='camera'. ScreenTile отдельный stable source='screen'. RoundStage создает локальные UI card keys cameraId / screen:ID, общая пагинация6/4, primary+3, максимум12 video elements при экране11+1. Все камеры по-прежнему смонтированы между страницами; выбор screen меняет только экранный элемент. Dock получает screen кнопку/strings/icons, media pending semantics сохраняется. ParticipantActions fallbackrange0..200, явные local actions, pin включает speaker. Стили сохраняют «Реплику»/желтый акцент/44px targets, узкие плитки не должны обрезать popup.

## Уточнение после независимого ревью v1.1
Все три независимых обзора выявили одну подтвержденную дыру текущего lifecycle: ownershipLost обнуляет session, не закрывая ее. Перед потерей ссылки root сохраняет прежний экземпляр и инициирует disconnect (его screen revision/stop должны происходить до первого await), без api.leave, чтобы не затронуть новую вкладку. Adapter также инвалидирует экран и останавливает известный track в самом RoomEvent.Disconnected, включая ненетевые причины, а не только в явном disconnect. Regression: pending/active capture при ownership loss и SDK disconnected, поздний capture/publish не возвращает показ. Проверять raw readyState после capture/publish: browser ended во время публикации не должен оставить поздний активный sender. Остальные точки переиспользования, source budget и границы grants приняты обзорами.

## Реализация и проверка
Выполнены личные действия/200%/camera-hide/pin и отдельный screen lifecycle. На маленьких карточках шириной до190px камера доступна в More, до148px там же полная громкость; прямой pin остается. Это сохраняет44px цели вместо наложения. Подпись скрытой камеры перенесена в tile-caption, поскольку внутри силуэта она пересекалась с кнопками в низкой ленте. Source-specific keys сохраняют вебку при добавлении/выборе экрана. Финальные docs/spec/design/architecture обновлены; AGENTS/CLAUDE не менялись.

Независимые implementation reviews нашли и закрыли два случая: дубликаты источников (11камер+два ScreenShare давали14 видеоподписок вместе с дополнительной Camera; теперь выбран ровно один SDK publication каждого source, остальные отписаны/беззвучны) и pointerFocus после mouse-down с отпусканием вне кнопки. Для обоих воспроизведен RED и добавлены постоянные регрессии; повторные независимые обзоры закрыли замечания. Security review подтвердил границы grant/комнаты/latecapture; это не доказательство серверного ACL комнат, которое по-прежнему вне MVP.

Финальная проверка:604 FE tests в54файлах одним запуском; после уточнения accessible-description неподдерживаемой кнопки повторно26 responsive tests.
