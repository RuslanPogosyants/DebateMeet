# Порядок управления и равная сетка

План v1.2, 30.10.2026. Автор поручил поднять инфраструктурную строку над дебатными данными и показывать равные плитки по умолчанию, увеличивая человека при ручном pin. Двух участников также показываем равными (озвучено в чате). Рабочие изменения предыдущих задач сохраняются; backend и транспорт не меняются.

## Решение

В `Meeting` первым внутри центральной колонки идет существующий scene-toolbar (панель/комната/очередь рук/судья/вид). Ниже — scene-round-header с резолюцией, инфослайдом и прежним таймером. Потом индикатор записи и видео с нижней панелью звонка. Нижние микрофон/камера/выход сохраняют свое положение. Переносится существующий toolbar целиком, без дубля кнопок и без изменения video DOM.

`MotionDisplay` показывает резолюцию и заданный инфослайд обычным шрифтом чата 15px/21px. Длинный summary ограничен по высоте и прокручивается, «Полностью» продолжает открывать весь текст. Поле инфослайда plain text с переносами, без HTML. Пустой инфослайд не добавляет строку. Дебатная строка не отнимает всю высоту сцены даже при максимальном тексте; мобильная раскладка и доступ к полному тексту сохраняются.

`SceneSession` всегда стартует в grid, включая старый localStorage со speaker. Размер и порядок плиток не меняются от speaking; обводка активности остается. Удаляется таймер/гистерезис автоматического выбора крупного человека: primaryId как дубль pinnedId удаляется; primary key выводится в RoundStage из допустимого pin/явно увеличенного экрана. `pin(id)` включает крупную плитку, `pin(null)` и «Сетка» возвращают равную сетку. Уход закрепленного, hide pinned self и смена комнаты снимают pin и возвращают grid. Обычная потеря/возвращение голоса не меняет режим.

Кнопка произвольного «Крупного спикера» без pin убирается из SceneControls; остаются «Сетка» для снятия закрепления и self-view. Прямые pin на плитках сохраняются. Управление демонстрацией отдельно не переосмысливается: явная кнопка «Показать экран крупно» по-прежнему увеличивает выбранную демонстрацию; сам факт появления экрана при grid не увеличивает камеру. После окончания явно увеличенной демонстрации возвращается grid, даже если другой экран еще активен; другой можно увеличить вручную. Явный dropdown может сменить экран внутри уже увеличенного режима. Камера pin имеет прежний приоритет над экраном. Старый sceneLayout preference может оставаться в storage/API для совместимости, но Session больше его не читает/не пишет; дефолт BrowserPreferences — grid.

## Изменения и приемка

- `round-page.tsx`/styles.css: перенести toolbar перед дебатным header, поправить grid rows и spacing. Контролы у верхнего края; header ниже; mobile не получает горизонтальный скролл. Tile/video refs не меняются.
- `round-motion.tsx`/styles.css: компактный summary с plain-text инфослайдом, максимальная высота около 96px и отдельные actions; таймер сохраняет размер/действия. Кнопка полного текста остается с клавиатуры и touch.
- `scene-session.ts`: удалить candidate/clock/timer и использование subscription ids для автоматического primary. Сохранить eligible/room/12-11 budget/viewport requests/hidden cameras/pin validation. Сигнатура constructor только Preferences, update — snapshot/self/people. Root controller и существующие тесты адаптировать напрямую, без нового слоя.
- `SceneControls`/зависимые E2E: больше нет отдельного выбора человека по голосу. Grid снимает pin, повторное увеличение — через прямую кнопку на плитке. Tests закрепляют нужного человека вместо записи primaryId напрямую.
- Проверить 2/3/4 человека равного размера без pin, legacy speaker preference, speaking frames через прежние интервалы ничего не увеличивают; pin/unpin/leave/room/self-hide и явную демонстрацию. Проверить бюджет и отсутствие новых attach при простой смене speaking.
- Header и полный инфослайд проверить UI tests и браузером актуальной сборки на 1600×1000/1280×720/390×844 с длинным текстом. Реальные локальные API/LiveKit, тестовые участники/устройства и фиктивный audio output. Использовать собственный существующий раунд; не расходовать create-квоту, не запускать длительных тестов. Frontend tests/lint/types/layers/build/budget.

Предыдущий общий roster остается скрытым, левая панель и локальная запись продолжают работать. Явных серверных действий от перестановки/говорящего нет. Новые авто-переходы/фазы/перемещения/мьюты не добавляются.


## Независимое ревью

Два read-only обзора: инженерный подтвердил reuse и поддержал удаление лишнего primaryId; behavioral выявил неоднозначность, если увеличенный A завершился при активном B. В v1.1 исчезновение выбранного увеличенного экрана возвращает grid; оставшийся экран выбирается для selector, но не увеличивается автоматически. Ручная смена через dropdown сохраняет увеличенный режим. Переход проверяется с двумя экранами. Других существенных противоречий нет, реализация разрешена исходным запросом.


Инженерное уточнение v1.2: TimerHealth переносится в существующий meeting-notices в обычном потоке. Старый absolute overlay над central header удаляется; здоровый TimerHealth возвращает null, чтобы пустой wrapper не создавал лишнюю строку. Проверка с degraded/playbackBlocked на 390px подтверждает, что предупреждение находится над toolbar и не перекрывает кнопки. Новый набор уведомлений не создается.

## Коррекция v2: иерархия и два ручных режима

Запрос автора: жирное «Резолюция:», дебатный текст заметнее инфраструктуры, счетчик рук без обрезания, вернуть второй вариант рядом с «Сеткой». Это корректирует предыдущее решение об удалении кнопки; дефолт остается grid, говорящий не выбирается автоматически.

- В MotionDisplay вынести «Резолюция:» в strong, выделить также префикс инфослайда; резолюция 17px/24px, medium, инфослайд прежние 15px/21px regular. Summary по-прежнему до 96px с полным текстом в Sheet.
- В существующей scene-heading уменьшить название комнаты до 16px/20px medium; верхние иконки 18px в кнопках 32px для mouse, 44px для coarse pointer. RoomsPanelToggle получает те же размеры в своем CSS. Нижние controls не меняются. Toolbar padding-block 6px резервирует место над badge, счетчик 18px с inset -4px, не выходит за workspace; проверить реальные bounds и screenshot на desktop/mobile.
- Вернуть кнопку «Крупный спикер» через имеющийся SceneControls и text.speaker. SceneSession.setLayout('speaker') сохраняет текущий pin; при выбранном экране увеличивает его; иначе вызывает существующий pin(id) для первого допустимого собеседника (eligible id != self), при отсутствии собеседника — self, при пустом eligible — no-op. Никаких clock/speaking/timer или новых состояний. SetLayout(grid) снимает pin как прежде. Выбор от явного клика, не автоматический.
- Повторный speaker не меняет pin; смена speaking ничего не меняет; уход pinned/смена комнаты/self hide возвращают grid. Увеличенный экран, который закончился при другом экране, все еще возвращает grid. Подписки и бюджет 12/11 не меняются. Pin на плитках сохраняется.
- Обновить старые ожидания отсутствия кнопки/игнорирования speaker и добавить поведенческие проверки обоих переключателей, no-op пустой сцены и одиночного self.
