# Сетка участников без общего меню

План v1.1, 30.10.2026. Автор поручил скрыть ненужный список участников и большое меню закрепления, сохранив код на будущее, и сделать несколько видеоплиток аккуратнее. Предыдущие рабочие изменения записи и единой левой панели сохраняются. Реализация разрешена исходным запросом; новая серверная функциональность, удаление участников и фильтры сообщений не добавляются.

## Поведение и выбор

Убираем публичные входы общего списка: кнопку «Участники» в нижней панели и ссылки «Все N» карты комнат. В карте остается неинтерактивное «Еще N» с индикатором поднятых рук. Убираем многоточие большого ParticipantActions с плиток. Прямые компактные pin/громкость/скрытие камеры остаются; общий компонент большого меню сохраняется в коде без feature flag. Очередь поднятых рук и ручные полномочия судьи остаются; вместо входа в общее меню там доступны непосредственно судейские действия (опустить руку, выключить/попросить включить микрофон), с прежними guards.

Сетка получает расстояния 8–10 px, скругленные края 10 px и тонкую нейтральную границу. Фон выключенной камеры отличается от сцены, вместо большой одинаковой силуэтной иконки — инициалы в нейтральном круге. Подписи и статус микрофона остаются небольшими overlays; здоровое/неизвестное качество не засоряет каждую подпись, проблема связи остается видна. У 4 участников — 2×2, у 3 — 2+1 по центру, у 5 — 3+2 по центру; 6 — 3×2. Mobile показывает до четырех плиток на странице. Режим крупной плитки/демонстрация и ручной pin сохраняются. Новых автоматических переключений спикера нет.

Удаление списка не должно делать участников с 13-го недостижимыми. Сейчас SceneSession держит 12 камер (11 при демонстрации), RoundStage строит страницы только из этого набора, а остальные доступны лишь через список. Поэтому страницы строятся по всем подключенным участникам своей комнаты (до 40), а attachVideo разрешен только для текущего bounded набора SceneSession. Небольшой метод `setVisibleVideoIds(ids)` сообщает сцене нужные камеры страницы; они получают приоритет внутри существующего бюджета, затем сохраняются прежние слоты. Ручной pin остается обязательным слотом. Это не рост бюджета и не новая RTC-сессия. HTML video elements вне набора не привязываются к SDK; элементы текущего набора сохраняются при layout/collapse. Переход страницы может освободить прежние слоты и подписать новые — это намеренное ограничение ресурсов.

## Точки переиспользования и план

- Meeting/RoomMap: снять входы RoomRosterButton/ParticipantRoster, сохранить count и hand summary. Ненужный общий UI не скрывается одним CSS (включая keyboard/ARIA).
- ParticipantActions: выделить существующие судейские кнопки в `JudgeParticipantActions`; использовать напрямую в JudgeSocialPanel и очереди рук. ParticipantRoster получает необязательный renderActions для очереди, сохраняя pagination и прежний общий вариант в коде.
- RoundStage: все roomParticipants в карточках и страницах; `subscribed` для camera effect по SceneSession.videoIds; эффект сообщает видимые камеры. Стабильные key/ref и existing attachVideo остаются. Аватар с инициалами — небольшой UI helper в том же файле, новых моделей/зависимостей нет.
- SceneSession: частный запрос видимых ids, сверка с eligible, бюджет 12/11, pin-first, очистка на смене комнаты/close; первоначальные слоты/существующая логика primary без запроса не меняются.
- styles.css: обновить существующие grid/tile правила; UI regression и scene-session tests; docs/design и spec фиксируют новое решение.

## Приемка

1. В настоящем экране нет общего списка «Участники», ссылок «Все N» и больших меню «Действия — …»; в том числе на mobile. Нет новых kick/chat-filter функций. Прямые pin/volume/camera работают.
2. Судейские действия и очередь рук с pagination остаются доступны без общего меню. Команды, авторизация и disabled-state прежние.
3. Все 40 подключенных участников своей комнаты достижимы через страницы; скрытый self и другие комнаты исключены. Во время каждого шага не более 12 video registrations с учетом экрана. Pin человека за прежними первыми 12 дает правильную крупную плитку; смена комнаты и уход участников не оставляют старый запрос/пустую страницу.
4. Сетка 1–6 участников выглядит цельно на 1600×1000/1280×720/390×844, видны границы и читаемы подписи; odd row центрируется, нет горизонтального скролла/вытеснения controls. Экран остается contain, камера сохраняет прежнее кадрирование. SVG/avatar без серверных изображений.
5. Tests проверяют отсутствие публичных входов, команду судьи напрямую, budget/страницы 40 человек, DOM stability неизменных slots и room fences. Браузерная проверка актуальной сборки с искусственными клиентами/видео и фиктивным audio output, включая camera-off avatars и 3/4/5/6 плиток, desktop/touch. Frontend unit/lint/types/layers/build/budget. Длительных/звуковых прогонов нет.

Ориентир — адаптация плиток к числу участников/размеру окна, описанная Google Meet: https://support.google.com/meet/answer/9292748 . Наша сетка остается явной и управляемой пользователем, без переноса чужих автоматических политик.


## Независимое ревью v1 → v1.1

Оба read-only обзора подтвердили reuse SceneSession/attachVideo и выявили одну проблему: старые container rules скрывают camera/volume, полагаясь на большое меню. В v1.1 эти display:none правила снимаются. На обычных touch-плитках остаются зоны 44px, на миниатюрах ≤160px — 32px, ≤120px — 28px без промежутков и с минимальным inset. Три прямые кнопки остаются достижимыми без открытия нового меню; минимум выше 24px. Браузерная проверка явно нажимает volume/camera на плитках около 170/140/110px, проверяет их bounds и отсутствие обрезания. Сетка/крупная плитка не переключаются ради доступа к ним. Судейские кнопки также компактные inline icons с полными aria-label вместо дополнительного диалога. Остальной план не изменен; исходное поручение разрешает реализацию.
