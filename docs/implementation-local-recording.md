# Локальная запись комнаты

## Разрешенный сценарий и основа

Автор разрешил реализацию 30.10.2026 после обсуждения сценария. Основа `e4674d1`, чистый checkout; параллельно делается сворачиваемая левая карта комнат по `implementation-collapsible-rooms.md`. Существующие grid/pin/демонстрация экрана сохраняются, новый active-speaker UX не добавляется. Публикация, merge и deployment не поручены.

Записываются изображение выбранной вкладки DebateMeet, ее звук и собственный включенный микрофон. Другие приложения не записываются. Alt+Tab/другая вкладка не прерывают запись. Одна запись принадлежит одной логической комнате: stop/leave/enter/recall/потеря сессии завершают захват до нового изображения/звука. Новый вход не возобновляет старый захват. Нет ограничения длительности, получасового деления, автоматического окончания по таймеру/тишине и срока удаления после выхода. Записывающий видит «Идет запись · 42:15» и stop, остальные — «Имя ведет запись». Видео только на клиенте. Сервер хранит краткоживущую координацию, но не видео.

## Текущее устройство и переиспользование

- `LiveKitMediaSession` — единственный владелец tracks/subscriptions/volume, уже имеет AudioContext, cancel-safe screen lifecycle. Добавляем read-only источник собственного микрофона и режим фоновой записи, без второго getUserMedia/RTC подключения и без влияния на публикацию микрофона. Отдельный mic gain отражает mute и замену устройства. Микс вкладки включает таймер; mic добавляется только один раз.
- `RoundController.accept` применяет snapshot через SubscriptionManager; запись останавливается перед apply при смене epoch/своей комнаты/удалении self. `command(enter)`, `leave`, `ownershipLost`, `disconnected`, `pageHidden`, `dispose` синхронно останавливают capture до await/смены источников. Короткий reconnect того же MediaSession возможен только пока действует recording lease; новая media session заканчивает старую запись.
- `Services`/`main.tsx` — композиция RecordingApi/LocalRecordings/Recorder. UI не импортирует infrastructure. Новый `RecordingSession` владеет orchestration и Zustand status; `RoundController` дает текущие room/session и lifecycle. Локальная библиотека доступна на стартовой, prejoin/left и в More, независимо от доступа к серверному раунду.
- Backend использует существующие bearer credentials, `verify`, Connected/SID, bounded command_transaction и round row lock. Новая отдельная таблица не меняет Round JSON/schema/snapshot budget и исторические goldens.

## Технический выбор v1

1. Browser adapter захватывает current tab с явным разрешением непосредственно из click. После результата проверяет browser surface и Capture Handle текущего приложения/вкладки; захват окна/монитора/другой вкладки отвергается с остановкой tracks. Audio track вкладки обязателен. Неподдерживаемый браузер получает понятное объяснение. Pending capture cancel/late success не включает запись после выхода.
2. MediaRecorder кодирует WebM встроенным кодером браузера, стартовый бюджет до 1080p/24fps; текст/экран проверяются в native prototype. Небольшие порции последовательно пишутся OPFS worker с bounded queue и committed offsets/метаданными. Worker не строит весь файл в RAM. Запрашивается persistent storage; отказ явно отражается в UI. Никакой автоматической очистки несохраненных записей.
3. Capture/OPFS/экспорт и восстановление сначала проверяются настоящими browser APIs с искусственным видео/звуком на localhost. Нельзя обещать точный максимум потери хвоста: выдача chunks не имеет жесткого тайминга. Восстановленный результат должен реально воспроизводиться. Если continuous WebM без корректного конца невоспроизводим, исправляем контейнер потоково, без декодирования всего видео. При невозможности этого не объявляем функцию принятой.
4. Экспорт готового локального файла потоковый в выбранный файл (File System Access при наличии); доступный fallback через Blob URL файлового объекта без ArrayBuffer всего файла. Сам вызов download не удаляет временную копию. Удаление отдельное с подтверждением. Файл содержит комнату и дату, без секретного round id. Metadata локально допускает round id только как локальную связь, в DOM имени/логах его не показываем.
5. Серверная lease одна на логическую комнату. Это минимальная реализация запрета записывать человека одновременно двумя штатными рекордерами, т.к. медиа принадлежит одной текущей комнате. POST reserve/renew/stop и GET status, авторизация существующим participant secret + текущий SID. UUID recording id обеспечивает идемпотентность и fencing позднего stop/renew. Время lease 15с, heartbeat 3с, один запрос в полете. Клиентный deadline отсчитывается от monotonic начала запроса с запасом до серверного expiry, просроченный ответ не продлевает право. Перед append проверяется deadline; просроченные chunks не сохраняются. Истекшая lease не может возродиться через renew; нужен новый start/новый файл. Неподтвержденный reservation не показывается как активная запись; после MediaRecorder.start подтверждается active. Серверное чтение live status ограничено шестью комнатами; UI опрашивает без накопления запросов.
6. При потере сети heartbeat может повторяться в пределах действующей lease. До ее истечения capture останавливается и локальный файл завершается; новый серверный слот не выдается раньше expiry/явного fenced stop. Pagehide best-effort stop с keepalive, expiry освобождает слот после аварии. Срок lease никак не удаляет локальное видео.

## Приемка

A. Start: cancel/reject/wrong tab/missing tab audio/storage failure/lease conflict оставляют звонок и mic как были, не оставляют capture/sender/lease и ложный recording status. Late chooser/HTTP после cancel останавливается и не воскрешает запись.
B. Содержимое: настоящее видео+звук выбранной вкладки, собственный mic только включенный, mute/unmute/device switch без второго захвата и дубля голоса; screen share и запись работают независимо. AltTab/скрытая вкладка продолжают изображение/таймер/звук. Grid/pin/collapse не remount media.
C. Room/session boundary: enter/recall/epoch/leave/removed/replaced/full reconnect/dispose останавливают capture до новых медиа, предыдущие байты доступны локально; обычный короткий reconnect ограничен lease. Новая запись запускается вручную.
D. Хранение: normal stop, close/relaunch, аварийная остановка, частично записанный последний chunk/metadata, quota/write error, repeated export/delete. Нет TTL; библиотека работает без входа и в том же browser profile/origin. Private mode/очистка сайта не дают гарантий восстановления, готовый экспорт — обычный файл пользователя.
E. Координация: два конкурирующих start в одной комнате дают одного владельца; разные комнаты независимы; wrong secret/SID/room/epoch, stale renew/stop/UUID и deleted round не дают чужую lease. DB tests с настоящим изолированным Postgres, boundary HTTP tests с fakes.
F. Производительность: bounded queued bytes, последовательный disk writer/flush, отсутствие повторного encode и огромных ArrayBuffer при export/recovery; worker не блокирует UI; initial JS budget <=150 KiB gzip с lazy recorder. Native synthetic recording/playback/storage proves browser encoding/recovery, не физические устройства и не все браузеры. Реальная сборка UI на desktop/phone, scene/screen/pin и recovery после перезапуска. Локальные тесты/type/lint/layers/build/budget; не запускать инфраструктуру поверх пользовательского сервера.

## Неопределенности и граница доказательств

Самые существенные технические неизвестные — recovery continuous WebM и self-tab capture/background behavior. Их закрывает prototype до утверждения реализации. Без нативного chooser выбранной тестовой вкладки нельзя объявлять принятой настоящую запись вкладки; синтетическая MediaStream проверяет только recorder/storage. Нет обещания абсолютной защиты от внешней записи экрана, очистки браузера или потери диска. Счетчик обозначает активный encoder; замедление disk writer и остановка сообщаются отдельно.


## Уточнения независимого ревью v1.1

Два независимых behavioral/engineering обзора подтвердили reuse и выявили одинаковые уточнения: проверять Capture Handle не только после chooser, но на capturehandlechange/ended и перед каждым принятым chunk, запросить surfaceSwitching=exclude; при потере identity отбросить текущий chunk и завершить capture. Перед stop из snapshot проверить newerSnapshot(subscriptions.latest,next), чтобы запоздавшая версия другой комнаты не завершала новую корректную запись.

Отдельный независимый обзор проверяемости добавил межвкладочную библиотеку: WebLock на весь writer/drain/finalize; соседняя вкладка не восстанавливает/не экспортирует/не удаляет живую запись. После аварии lock освобождается и prefix доступен другой вкладке. Native-проверка выполняется настоящими страницами одного browser profile/origin.

## Browser adapter: реализация и проверка 30.10.2026

`BrowserRecordingPlatform` захватывает только текущую вкладку с проверкой Capture Handle до старта, на событии смены источника и перед каждым chunk. `surfaceSwitching=exclude`; другого окна/вкладки/аудио без вкладки недостаточно для старта. Собственный микрофон заимствуется у существующего MediaSession, не захватывается заново и не останавливается адаптером записи. Тот же raw track не создает новые WebAudio nodes при повторном уведомлении. Stop синхронно выключает capture, затем завершает encoder и очередь disk writer.

OPFS worker пишет непрерывный WebM порциями через буфер до 1 MiB; общая очередь ограничена 32 MiB. После flush данных записывается checksum-журнал committed offset; неполная последняя строка/лишний хвост данных не меняют подтвержденный префикс. WebLock на UUID удерживается от создания до завершения disk writer; соседняя вкладка получает recording_busy при экспорте/удалении живой записи. Проверяются оба срока lease: absolute monotonic (с учетом различающихся timeOrigin окна/worker) и wall clock. TTL удаления локальных файлов нет.

Для WebM без Duration первый заголовок получает восьмибайтовый placeholder. Завершение/восстановление обновляет только это значение; checksum нормализует поле Duration. Фильм не перекодируется и не собирается целиком в ArrayBuffer. Экспорт — OPFS-backed File; пользовательский файл создается через object URL. Неизвестная форма контейнера отвергается, а не изменяется предположительно.

Проверки: **18 целевых тестов пройдены** в recording-platform/WebM/recording-media. Последний использует настоящие Room, LocalTrackPublication и LocalAudioTrack установленного SDK с управляемыми браузерными узлами: mute/unmute, замена raw track, немедленный null до окончания mute/disconnect, shared adaptive settings. Собственные файлы прошли type-aware oxlint без suppressions; общий frontend typecheck прошел на момент проверки.

Явная native-проверка `node scripts/check-recording-native.ts` прошла на настоящем оконном Chromium. Источник — только собственная тестовая вкладка с canvas, синтетическим тоном вкладки 440 Hz и заимствованным синтетическим микрофоном 880 Hz; личный экран, камеры и физический микрофон не захватывались. При фокусе другой вкладки сохранены видео/аудио; амплитуда микрофона включен/выключен/включен: 0.9246 / 0.0000233 / 0.6802. Завершенный файл 186680 bytes воспроизводится, Duration 5.151 s; download сохранен и проверен. Вторая страница того же origin видит recording и не может экспортировать/удалить живой файл. Browser.crash → новый процесс с тем же profile восстановил 88321 bytes, Duration 2.100 s, воспроизводимые видео/звук; добавленные после committed offset мусорные байты и неполная строка журнала исключены из экспорта. Удаление восстановленной записи тоже проверено.

Это подтверждает browser encoding/storage/recovery и отдельный SDK seam на искусственных источниках. Длительная запись полной игры, фактическая нагрузка слабого ПК, физические устройства, все браузеры и поведение при сне ОС этим коротким прогоном не доказаны. Headless Chromium отказал getDisplayMedia; native-проверка поэтому использует headed browser с автоматическим выбором строго тестового заголовка. Восстановление не обещает сохранность последнего незафиксированного chunk, очистки данных сайта или потери диска.

## Browser corrections после implementation review

Проверяются возвращенные byte counts всех OPFS writes: media block, строка журнала и оба восьмибайтовых Duration patch (finish/recovery export). Short write возвращает recording_storage; journal offset продвигается только после полного write и flush. Новый harness исполняет настоящий recording-worker module с управляемыми OPFS/lock границами: неполная строка журнала отвергается, повтор идет по прежнему offset; неполный Duration при finish не создает ready commit и освобождает lock; неполный Duration при экспорте не выдает файл, повтор восстанавливается; неполный media write не подтверждает новые байты.

Подтвержденный lease/drain дефект исправлен immutable acceptance fence: каждый chunk получает source-validated acceptance timestamp и снимок действовавшего deadline; worker проверяет эти значения и сохраняет ранее принятые данные даже после истечения lease, не продлевая серверное право записи. Последний chunk штатного stop получает fence в момент синхронной остановки до выключения tracks; поздний callback не теряет безопасный хвост. Новые данные после expiry отвергаются. Ошибка storage отдельно блокирует последующие disk jobs, чтобы не продолжать файл через пропущенный блок. Регрессии проверяют pre-expiry acceptance/post-expiry drain и callback последнего chunk после expiry, а также отказ post-expiry acceptance.

Усиленный native script прошел без Playwright default flags disable-background-timer-throttling, disable-backgrounding-occluded-windows и disable-renderer-backgrounding. На обеих страницах после навигации выключен CDP focus emulation. При foreground другой вкладки source.hasFocus=false, other.hasFocus=true; visibilityState выбранной для capture вкладки остался visible (наблюдение Chromium, не принудительная эмуляция hidden). Внутри этого интервала источник изменен красный → синий; два seeked в экспортированном видео проверяют timestamp и декодированные RGB pixels именно этих двух состояний. Это закрывает прежний пробел проверки, где videoWidth/currentTime доказывали только воспроизведение начала файла. Получен воспроизводимый файл 149854 bytes, Duration 4.795 s; последний seek currentTime 3.8999 s. Микрофон on/off/on: 0.9077 / 0.0000552 / 0.9845. Повтор crash/relaunch/partial-journal recovery также прошел: 58093 bytes, Duration 2.096 s, видео и оба звуковых источника.

После исправлений **27 targeted tests** platform/worker/WebM/media seam прошли; typecheck и targeted type-aware oxlint прошли без suppressions. Harness short-write/drain проверяет настоящую worker-логику с подмененной OPFS границей; native tab-switch/seek/audio/recovery проверяет настоящие browser APIs на синтетических источниках. Полная игра и физические устройства этим по-прежнему не подтверждены.


## Итоговая интеграция и локальная приемка

Root закрыл независимые implementation findings: microphone seam следит за Restarted/Ended, ActiveDeviceChanged и результатом selectDevice, включая перезапуск с тем же device id; failedmute восстанавливает фактически работающий input, поздний toggle не отменяет suppression нового. Неподтвержденный startup при потере контекста завершается по revision. Ошибка чтения recording status сохраняет последние сведения с явным unavailable текстом. Ошибка экспорта не исчезает после обновления списка. Для каждого случая добавлена постоянная регрессия; повторное независимое ревью подтвердило закрытие.

Финальный frontend: **676 тестов в64файлах прошли** одним запуском; общий type-aware oxlint, Prettier, typecheck и dependency-cruiser (83модуля/297связей) прошли. Production build и initial JS budget прошли: **119,3КБ gzip при бюджете150КБ**. Worker загружается по необходимости; app не перекодирует фильм при экспорте. Полный backend на промежуточной версии дал **870pass/1skip**; после дополнительной защиты живой lease при смене epoch все **5 целевых Postgres/HTTP тестов записи** прошли. Skip — существующий webhook/RTC test, требующий свободный8000; действующий пользовательский dev backend занимал порт. Backend mypy, ruff/format и15 import contracts прошли. Общий E2E набор поверх пользовательского сервера не запускался.
