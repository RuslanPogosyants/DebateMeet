# Пробный стенд VDSina на неделю

Дата решения: 30.10.2026. Автор выбрал VDSina и бесплатные имена sslip.io для первой публичной пробы DebateMeet. Это временный стенд; постоянная схема стенд → прод из архитектуры не считается развернутой.

## Заказ

- Один стандартный VPS в Москве: 4 vCPU, 8 ГБ RAM, 150 ГБ NVMe, один публичный IPv4, чистая Ubuntu 24.04 LTS.
- Опубликованная цена: 80 рублей в день, 560 рублей за семь дней. Порт 1 Гбит/с, 32 ТБ трафика за календарный месяц. Фактическую цену и наличие проверяем в форме заказа.
- Целевой сценарий: два параллельных раунда примерно по 10–12 участников; первая пробная игра длится около трех часов. Это исходное предположение для подбора ресурсов, а не подтвержденная нагрузочная приемка.
- Домен не покупаем. Имена приложения, LiveKit и TURN получаются из фактического публичного IPv4: `app.<IPv4-с-дефисами>.sslip.io`, `livekit.<IPv4-с-дефисами>.sslip.io`, `turn.<IPv4-с-дефисами>.sslip.io`.
- Сертификаты выпускаются отдельно для трех имен через существующий Caddy/ACME. Проверяем DNS и HTTPS из внешней сети; доступность стороннего DNS и выдача сертификатов пока не подтверждены.

Источники: [тариф](https://vdsina.ru/pricing/standard), [минимальный баланс для конфигураций](https://vdsina.ru/plans-min-costs), [sslip.io](https://sslip.io/).

## Подготовка и ограничения

- Аккаунт VDSina создан на подключенную почту; автор отдельно подтвердил регистрацию и установил пароль самостоятельно. Отдельный публичный SSH-ключ `debatemeet-vdsina-trial` добавлен с явного подтверждения автора. Приватный ключ остается на Mac.
- В форме заказа проверены Москва, Ubuntu 24.04, 4 vCPU / 8 ГБ / 150 ГБ, 80 рублей в день; платный бэкап выключен. Провайдер отклонил создание из-за нулевого баланса. В Safari открыт переход в ЮKassa для пополнения на 560 рублей, сохранение способа оплаты выключено. Платеж и создание VPS пока не подтверждены.
- SSH-доступ готовим отдельным ключом. Приватный ключ и серверные секреты хранятся вне отслеживаемых файлов; их не вставляем в отчет, коммит или PR.
- Секреты базы и LiveKit, адреса и почта ACME находятся в локальном игнорируемом `deploy/server/.env.vdsina-trial`. До получения IPv4 адреса остаются незаполненными; этот файл нельзя применять к серверу как готовую конфигурацию.
- Для сервера собираем образы `linux/amd64`. Локальный Docker на этой машине использует ARM, поэтому обычный `just images` без выбора платформы не подтверждает готовность образов для VPS.
- В рабочем дереве есть незакоммиченные продуктовые изменения. Их сохраняем; происхождение пробной сборки фиксируем отдельно. Не выдаем такую сборку за опубликованный или прошедший удаленный CI релиз.
- До настройки доставки проверяем существующий бандл локально. VPS не должен скачивать образы из зарубежных реестров: нужен перенос подготовленных образов либо реестр в РФ. Покупка платного реестра или S3 в бюджет этой пробы не включена.
- Тонкий агент пока не проверяет отсутствие участников перед обновлением. Автоматическое обновление во время пробных игр не включаем; способ доставки и отката должен быть проверен до первой игры.

## Проверки после получения доступа

1. Проверить VPS, архитектуру, диск, SSH и фактический публичный IPv4. Настроить доступ по ключу и проверить второе подключение до изменения текущего способа входа.
2. Настроить Docker, каталог `/srv/debatemeet`, секреты и сохранение данных Postgres. Использовать существующие серверные Compose, Caddy и LiveKit как основу.
3. Открыть TCP 80/443, TCP 7881 и UDP 7882; SSH ограничить доступом оператора, если его внешний адрес известен. Postgres, API LiveKit, метрики и TURN backend 5349 не публиковать наружу.
4. Проверить DNS трех имен, выдачу и доверие TLS-сертификатов, HTTPS API и WebSocket LiveKit.
5. Применить миграции, проверить health/version и вход по ссылке. Сохранить проверяемый идентификатор развернутой сборки.
6. Проверить два разных раунда, изоляцию логических комнат, переходы, камеру, микрофон, демонстрацию экрана, переподключение и подключение только через TURN/TLS.
7. Проверить целевую одновременную нагрузку, внешнюю сеть и устройства участников до назначения первой игры. Локальные тесты не заменяют эти проверки.
8. Согласовать дату окончания аренды. До удаления сохранить нужные данные; автоматическое удаление VPS без отдельного разрешения не настраивать. Сервер не считается остановившим начисления только потому, что его выключили.

Фактическое создание VPS, IP, DNS, сертификаты, платеж, развертывание и результаты проверок записываются после выполнения соответствующих действий.

## Уточнение автора и план v2: GitHub → пробный VPS

Автор подтвердил оплату 560 рублей и предоставил действующий VPS 30.10.2026: x86_64, Ubuntu 26.04 LTS, 4 vCPU / 8 ГБ / 150 ГБ. Переустановка на 24.04 не требуется: приложение работает в закрепленных Linux-контейнерах; доступность Docker/Compose и поведение сети проверяются на фактической ОС. Выданный пароль менять запрещено. Автор явно разрешил настройку через SSH, публикацию всей текущей локальной версии в GitHub и деплой через GitHub.

Цель: текущие локальные продуктовые изменения включены в публичный GitHub без секретов; сервер обслуживает эту же проверенную версию по HTTPS с работающим RTC и TURN/TLS. Ранее собранные dirty-образы не считаются результатом GitHub и не используются для итогового деплоя.

Выбранный путь доставки на пробную неделю: существующая задача `Images` в `.github/workflows/ci.yml` после успешной сборки и проверок на `push` в `main` сохраняет переносимый артефакт Linux/amd64. После успешного полного CI этого же main-коммита оператор скачивает артефакт через `gh` на Mac и передает его на VPS через SSH. VPS не обращается к GitHub или зарубежным реестрам; GitHub не получает SSH-ключ или серверные секреты. Это ручная доставка результата GitHub Actions, а не автоматическая выкатка после каждого merge. Постоянная registry/agent-схема остается отдельной работой.

### Переиспользование и изменения

- Сохранить существующие `backend/Dockerfile`, `frontend/Dockerfile`, `deploy/server/Dockerfile`, Compose, Caddy, LiveKit и вход миграций `python -m debatemeet.migrate`.
- Расширить только конец существующей задачи `Images`: пакетировать уже проверенные CI-образы и закрепленные Postgres/LiveKit/Caddy; загрузить артефакт только на `push` в `main` и только при успехе предыдущих шагов. Новый workflow, manual workflow dispatch, GHCR, платный registry и GitHub SSH-секреты не нужны.
- Добавить небольшой упаковщик в `deploy/trial/`: извлечь исходный бандл и статику из CI-образов; сохранить шесть образов, идентификатор git-коммита, версию, соответствие тегов/image IDs и SHA256 файлов. Серверные `.env`, ключи и почта не включаются. Проверить соответствие version labels и Linux/amd64, а также наличие файлов начального SPA.
- Добавить декларативный Compose override для trial: использовать исключительно загруженные образы с `pull_policy: never`. Конфигурация основной серверной схемы не меняется. Полный commit SHA передается как deployment version; после загрузки образы сверяются с манифестом.
- Не включать тонкий polling-агент для пробного VPS: его текущая версия не защищает активные раунды от рестарта. Первое развертывание выполняется вручную в пустую БД; обновления во время игр не выполнять.
- Сохранить все существующие локальные изменения отдельным коммитом на новой `codex/` ветке, интегрировать актуальный `origin/main` и провести полный CI через PR в `main`. Merge только при последнем зеленом `ci-ok` на вершине PR. Guardrail-файлы не менять. Указанный автором пароль не записывать в файлы, Git или CI.
- Настройка VPS: оставить выданный пароль, добавить уже согласованный отдельный SSH-ключ; проверить повторный вход. Использовать пакетный репозиторий в РФ для Docker и Compose, проверить адрес источника. UFW сохраняет SSH и разрешает только необходимые публичные TCP 80/443/7881 и UDP 7882; внутренние API, метрики, Postgres и TURN backend 5349 остаются закрытыми.
- Заполнить секреты и три sslip.io-имени только в защищенном серверном `.env`. TLS получает существующий Caddy. На VPS не собирать приложение из исходников и не делать `git pull`.

### Приемка и отклонения

1. GitHub содержит локальные изменения; перед merge проверены scope, секреты и релевантные локальные проверки. PR и полный `main` CI зеленые. Итоговый артефакт относится к точному main SHA, скачан из его успешного run, не из PR или произвольного старого run.
2. Артефакт не содержит `.env` и учетных данных; manifest/labels/version и SHA256 согласованы. Нет исходящих скачиваний образов с VPS. Ошибка проверки прекращает загрузку/выкатку до миграций.
3. После установки Docker и миграций backend healthy, `/api/health` сообщает ожидаемую версию. Приложение и LiveKit доступны по HTTPS/WSS с доверенными сертификатами; три имени резолвятся в назначенный IP.
4. Проверены два параллельных раунда, вход и RTC внутри раунда, отсутствие медиа между разными раундами, переключение логических комнат, камера/микрофон и TURN/TLS. Недоступная проверка явно остается незавершенной; HTTP 200 сам по себе не означает работающий звонок.
5. Пароль не изменен, SSH по ключу работает; порты БД/API/метрик/5349 снаружи недоступны. Платные дополнительные услуги, второй VPS и автоматическое удаление не добавляются.
6. При ошибке сборки/CI merge и деплой не выполнять; причину устранить в той же ветке. При ошибке DNS/ACME не отключать проверку TLS, а исправить реальную причину. При повторном запуске не удалять том Postgres и не переустанавливать ОС. Перед последующей миграцией непустой БД сделать дамп.

Сознательные границы: это один пробный стенд и ручная доставка артефакта GitHub; постоянный автодеплой, внешний S3 backup, Prometheus/Grafana и подтверждение физического эха не объявляются выполненными. Перед окончанием недели данные сохраняются и прекращение аренды согласуется отдельно.

План v2 подлежит независимому read-only ревью поведения/проверяемости и инженерии/безопасности перед изменением упаковки и CI. Факты SSH и проверки упаковки фиксируются ниже по мере выполнения.
