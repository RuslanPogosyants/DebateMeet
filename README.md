# DebateMeet

Площадка для раундов британского парламентского формата (БПФ): одна ссылка — один раунд.

Внутри раунда шесть комнат: база, OG, OO, CG, CO и судейская. Кроме них — общие таймеры, резолюция, жребий позиций, поднятые руки и общий чат. Платформа показывает и подсказывает, но никого не перемещает и не глушит сама: это делает только судья вручную.

Стек: LiveKit self-hosted, FastAPI, Postgres, React.

**Статус на 27 октября 2026, срез 3 поверх `2cb3ae6`:** реализованы локальные срезы 0а/0б и 1–3. Два независимых таймера управляются судьёй; «Следующая речь» имеет точную отмену. Клиенты синхронизируют часы, показывают защищённое время и грейс, а сигналы планируются на часах Web Audio. Следующий этап — резолюция, жребий и общий чат.

Актуальные доказательства — в [разделе 11 архитектуры](docs/architecture.md#текущий-статус-реализации). Проверены настоящее прохождение медиа через локальные Postgres/LiveKit, изоляция комнат, таймеры между комнатами и после перезагрузки, часы с разницей в пять минут, звук в действительно скрытой вкладке и строгий autoplay до первого нажатия. Исходники подготовительной версии A (`ca18693`) проверены в цепочке B → A → B; это совместимость кода, а не выполненный откат сервера.

Физическую проверку эха в Chrome на динамиках ноутбука автор отложил; до её результата громкость выше 100% не включается. Исправленный замер среза 2 с `netem` сохранил p95 звука **664 мс**, видео **998 мс** при задержке `100 ± 20 мс` и потерях `1%`. Удалённый зелёный CI, слияния, выкатка и приёмка на настоящей сети не подтверждены; стенд запланирован после шестого среза ([ADR 0001](docs/adr/0001-stand-after-slice-6.md)).

Подготовка среза 4 (A4) уже сохраняет резолюцию и жребий в снимке, читает историю чата и доставляет надёжные серверные пакеты. Пройдены 502 backend-теста, 226 клиентских тестов и десять E2E. Самих команд резолюции/жребия/отправки и их интерфейса пока нет: они добавляются после отдельной совместимой границы A4.

## Что нужно

- Docker с Compose;
- [uv](https://docs.astral.sh/uv/): Python 3.14 он поставит сам;
- Node 24 или новее и pnpm версии из `packageManager` в `frontend/package.json` (сейчас 12.6.0);
- [just](https://just.systems) и [lefthook](https://github.com/evilmartians/lefthook);
- системный `python3` 3.9 или новее — для git-хуков.

## Первый запуск

```bash
just setup
```

`setup` ставит зависимости бэкенда и фронтенда, git-хуки и создаёт `backend/.env` из `backend/.env.example`.

```bash
just dev
```

`dev` поднимает Postgres и LiveKit из `compose.yaml`, применяет миграции, затем запускает бэкенд на `:8000` и Vite на `:5173`. Откройте <http://localhost:5173>: создайте раунд, скопируйте ссылку и войдите в базу. Затем можно переходить между шестью комнатами и взять свободный флаг судьи. Микрофон при входе выключен; камеру выбирают перед входом. Ctrl-C останавливает всё, кроме контейнеров; их останавливает `just down`.

## Команды

| Команда | Что делает |
|---|---|
| `just setup` | зависимости, git-хуки, `backend/.env` |
| `just up`, `just down` | Postgres и LiveKit из `compose.yaml`; данные остаются |
| `just dev` | контейнеры, бэкенд и Vite вместе |
| `just dev-backend`, `just dev-web` | бэкенд или Vite по отдельности |
| `just test` | unit- и интеграционные тесты, включая Postgres и LiveKit |
| `just test-e2e` | собранное приложение и настоящий локальный стек; Chromium с поддельными камерой и микрофоном, изоляция звука, перенос вкладки и проверка измерителя выхода |
| `just measure-rooms` | отдельный локальный замер 30 переходов с задержкой `100 ± 20 мс` и потерями `1%` через `netem`; результат не заменяет проверку настоящей сети |
| `just lint` | линтеры, проверка типов и правила слоёв |
| `just fmt` | форматирование и безопасные автоисправления |
| `just contract` | перегенерировать `frontend/src/contract` из OpenAPI бэкенда |
| `just migrate` | довести dev-базу до последней миграции, как агент выкатки на сервере |
| `just migration 0004 "…"` | начать следующую ревизию схемы в `backend/src/debatemeet/migrations/versions/` |
| `just admin show ROUND_ID` | снимок раунда без секретов; остальные служебные команды приведены ниже |
| `just bots N` | N тестовых участников: у каждого тон и тестовая картинка |
| `just echo-check` | проверка эха на динамиках ноутбука: голосовой бот и страница замера для Chrome |
| `just images` | собрать образы `debatemeet-backend:dev`, `debatemeet-web:dev` и бандл развёртывания `debatemeet-bundle:dev` с версией текущего коммита |

Тест вебхуков LiveKit слушает порт 8000. Если запущен `just dev-backend`, этот тест пропускается. Для `just test-e2e` освободите порты 8000 и 4173; перед первым прогоном установите Chromium командой `cd frontend && pnpm exec playwright install chromium`. E2E создаёт отдельную временную БД на каждый прогон и удаляет её после остановки приложения; dev-данные и состояние предыдущих прогонов не сбрасываются. `debatemeet_test` служит родительским тестовым подключением; другое тестовое подключение задаёт `DM_E2E_DATABASE_URL`.

## Служебные команды

В dev выполняйте их из корня репозитория; настройки берутся из `backend/.env`:

```bash
just admin show ROUND_ID
just admin release-judge ROUND_ID
just admin remove-participant ROUND_ID PARTICIPANT_ID
just admin close-entry ROUND_ID
just admin open-entry ROUND_ID
```

`show` возвращает снимок с публичными id участников, без секретов и их хешей. Закрытие входа касается новых участников; повторный вход с действующими сохранёнными данными остаётся доступен. Удаление отзывает секрет и ставит удаление из LiveKit в transactional outbox: завершение CLI подтверждает запись команды, а фактическое отключение доставляет работающий публикатор. Команд удаления сообщений и самого раунда пока нет.

На сервере те же команды запускаются рядом с установленными `agent.py` и `compose.yaml`: `deploy/server/justfile` входит в бандл и использует `python3 agent.py compose exec -T backend python -m debatemeet.admin …` с файлами окружения текущего релиза. Наличие этого пути ещё не означает, что стенд развёрнут.

## Устройство репозитория

| Каталог | Что там |
|---|---|
| `backend/` | FastAPI, модульный монолит: контексты Раунд и Медиа, порты и адаптеры (раздел 4 архитектуры) |
| `backend/bots/` | боты для разработки и тестов против LiveKit |
| `frontend/` | React SPA, тот же гексагон, что на бэкенде (раздел 7) |
| `frontend/src/contract/` | схема OpenAPI и TS-типы, сгенерированные из бэкенда; руками не правятся |
| `deploy/dev/` | конфигурация Postgres и LiveKit для разработки |
| `deploy/server/` | бандл развёртывания стенда и прода: compose, конфиги Caddy и LiveKit, образец `.env` сервера, агент выкатки `agent.py`, серверный `justfile` для CLI и юниты systemd |
| `tools/git/` | проверка сообщений коммитов и заголовков PR |
| `tools/app-version.sh` | версия приложения для образов: дата и sha коммита |
| `.github/` | CI и Dependabot (раздел 10) |

Правила слоёв проверяют `import-linter` на бэкенде и `dependency-cruiser` на фронтенде — локально в `just lint` и в CI.

## Как вносить изменения

- Короткая ветка и PR в `main`, squash-merge, только при зелёной проверке `ci-ok`. Свои PR сливает Claude. PR, которые меняют ограничители Claude (`.claude/`, `tools/git/`, `lefthook.yml`), и PR ботов сливает автор.
- Сообщение коммита и заголовок PR — одна строка `type: description` на английском. Типы: `feat`, `fix`, `refactor`, `docs`, `test`, `chore`. Проверяют хук `commit-msg` и CI.
- Крупное решение сначала обсуждается и записывается в [ADR](docs/adr/).
- Проверка на телефоне — через стенд, он появится в срезе С: локальный LiveKit доступен только с этой машины.
- Репозиторий публичный: секретов и файлов `.env` в нём нет.

Лицензии пока нет: все права защищены.
